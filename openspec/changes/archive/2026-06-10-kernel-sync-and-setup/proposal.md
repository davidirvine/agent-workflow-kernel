## Why

Slice 3 ships the kernel as a **one-shot generator**: `new-app.sh` emits a fresh app and walks away. There is no path back — a consuming app cannot pull kernel improvements (fixes to hooks, new specs, updated workflow tooling) without re-generating from scratch and losing its own state. This slice (ROADMAP slice 4) ships the two scripts that turn the kernel into a **maintained** kernel: `sync-kernel.sh` re-pulls kernel-tier + stack-tier files into an existing app with clobber-protection and a kernel-version stamp (so sync is a deliberate bump, not an unbounded HEAD pull); `setup.sh` is the idempotent per-checkout setup with a `--check` mode, that *does* the repo-local deterministic work (`npm ci`, the preset's `prebuild` which compiles FAUST via the `@grame/faustwasm` npm dep, install hooks) and *verifies* global prereqs (`gh`, `openspec`, `roborev`, `jq`, Node per `.nvmrc`, `shfmt` at the pinned version) and instructs rather than auto-installing. (`faust` is deliberately absent from the prereq table — STACK.md is explicit that FAUST ships as an npm dep, not a system tool.)

## What Changes

- **Add `scripts/sync-kernel.sh`** — re-pulls kernel files into an existing consuming app. CLI: `--kernel-repo <path>` (required, the kernel checkout), `--app-repo <path>` (defaults to `.`), `--dry-run` (report without writing), `--accept-kernel` (overwrite locally-modified synced files). Reads `kernel-manifest.json` exactly as `new-app.sh` does. **Honors `excludeFromGenerate`** the same way (those files never travel — sync mirrors generation). **Re-applies `appTemplates`** with clobber protection (the kernel can ship a CI-template update; consumers get it on next sync). **Does NOT re-apply `instrumentStubs`** (instrument files are app-owned content after generation). Additive only — never deletes a file the consuming app has but the kernel doesn't (a kernel removal is informational, not destructive). **The script itself is added to `kernel.excludeFromGenerate`** (per design D3a) — it is a kernel-only tool the user invokes from the kernel checkout against a consuming app, so the running sync is always the kernel's current version (no self-update bootstrap problem).
- **Add `.kernel-version` stamp** at the consuming app's root — a single-line text file recording the kernel version the app was last synced from. `new-app.sh` is amended to write it at generation; `sync-kernel.sh` reads + advances it on each successful sync. The version source-of-truth is the kernel's `.release-please-manifest.json` `"."` value (already release-please-managed; no new versioning machinery). Sync is therefore "from X.Y.Z to A.B.C" — a deliberate bump with an upgrade path the user can read in the dry-run report.
- **Add `.kernel-sync-hashes.json`** at the consuming app's root — clobber-protection state. Records the SHA-256 of every synced file as of the last sync. Format: `{"version": 1, "syncedAt": "<kernel-version>", "hashes": {"<path>": "<sha256>", …}}`. On next sync: a consuming-app file whose current hash equals the recorded hash is unmodified → safe to overwrite; if it differs, the file was modified locally → sync **refuses** unless `--accept-kernel` was passed, listing every conflicting file. Committed to the consuming app's git so the state travels with the repo. `new-app.sh` writes the initial file on generation.
- **Add `scripts/setup.sh`** — idempotent per-checkout setup with a `--check` mode. Default mode: `npm ci` at root (and inside any preset directory present); run the preset's `prebuild` (which compiles the DSP via the `@grame/faustwasm` npm dep — **no separate system FAUST install**, per STACK.md); invoke `scripts/install-hooks.sh` (idempotent). `--check` mode: do no work; verify global prereqs (`shfmt` at slice-1's `v3.8.0`; `shellcheck`, `jq`, `gh`, `openspec`, `roborev`, Node from `.nvmrc`); report each missing tool with an actionable install hint; exit non-zero on any miss. `faust` is deliberately absent from the prereq table — STACK.md is explicit. **The same script runs in the kernel checkout and in any generated app** (layout auto-detect: presence of `presets/` ⇒ kernel layout; otherwise app layout).
- **Refactor: extract `expand_entry()` + the shared manifest-reading patterns into `scripts/lib/manifest.sh`** — the function is duplicated in `new-app.sh`, `generate-assert.sh`, and `check-manifest.sh` (slice 3) and slice 4 adds `sync-kernel.sh` + `setup.sh` (potentially a 5th and 6th copy). Source the lib (`. "$(dirname "$0")/lib/manifest.sh"`) from all five scripts; the existing scripts get a small DRY refactor with no behavior change.
- **Extend `kernel-manifest.json`**: add `.kernel-version` and `.kernel-sync-hashes.json` to a new `kernel.appStateFiles` field (declarative list of files `sync-kernel.sh` writes in consuming apps that are NOT subject to clobber protection — they are sync's own state). Add a `kernel.appOwnedFiles` field (per design D3d) listing the files `new-app.sh` customizes per app — `src/components/Shell.svelte`, `vite.config.js`, `package.json`, `.release-please-manifest.json` — which travel at generation but are excluded from the sync plan and hash record so a sync cannot clobber the app's identity/release state. Add `scripts/sync-kernel.sh` to `kernel.excludeFromGenerate` per D3a. (No new `kernel.paths` entry needed — the shared `scripts/lib/` directory is already covered by the existing `scripts/**` glob.)
- **Modify `scripts/check-manifest.sh`** to validate the new `appStateFiles` field (each entry is a non-empty literal path; targets do not appear in `kernel.paths` or in any preset's `paths`).
- **CI changes:** extend the `generate-assert` job with a three-step sync round-trip — positive (dry-run reports "up to date"), negative (modify a synced file, simulate a kernel bump, assert non-zero exit + conflict reported), and `--accept-kernel` (re-run, assert overwrite + hash-file updated). **No new `setup-check` CI job** in this slice — `setup.sh --check` is for humans + downstream consumers; the kernel's own CI continues to provision its prereqs explicitly. The `smoke-app` stub stays for slice 5.
- **Amend `new-app.sh`** to (a) write `.kernel-version` from the kernel's `.release-please-manifest.json`, (b) write the initial `.kernel-sync-hashes.json` for all kernel-tier files emitted, and (c) source `scripts/lib/manifest.sh` instead of inlining `expand_entry`.

## Capabilities

### New Capabilities

- `kernel-sync`: the contract `sync-kernel.sh` honors — manifest-driven re-pull into an existing app with clobber-protection (hash-file state), kernel-version-stamped bumps, additive-only changes, `excludeFromGenerate` honored, `appTemplates` re-applied, `instrumentStubs` never re-applied. A committed `--dry-run` reports the upgrade path before any write.
- `repo-setup`: the contract `setup.sh` honors — idempotent default-mode setup (`npm ci`, hooks activation, FAUST prebuild when applicable) and a `--check` mode that verifies global prereqs with actionable install hints, suitable for CI to gate runner readiness.

### Modified Capabilities

- `preset-portability`: add explicit requirements about what sync does — specifically, that `excludeFromGenerate` applies to sync as well as generation, `appTemplates` re-applies on sync, and `instrumentStubs` do NOT re-apply (the instrument is app-owned content). Plus an `appStateFiles` field declaring sync's own state files (the version stamp and the hash record).

## Impact

- **New script files:** `scripts/sync-kernel.sh`, `scripts/setup.sh`, `scripts/lib/manifest.sh`.
- **Modified script files:** `scripts/new-app.sh` (write `.kernel-version` + `.kernel-sync-hashes.json`; source the lib), `scripts/generate-assert.sh` (source the lib; assert sync round-trip), `scripts/check-manifest.sh` (source the lib; validate `appStateFiles`).
- **Modified manifest:** `kernel-manifest.json` gains `kernel.appStateFiles`; `scripts/sync-kernel.sh` is added to `kernel.excludeFromGenerate` per D3a. (No new entry for `scripts/lib/**` is needed — the existing `scripts/**` glob already covers it.)
- **Modified CI workflow:** `.github/workflows/ci.yml`'s `generate-assert` job is extended with the three-step sync round-trip (positive dry-run, negative conflict, `--accept-kernel` resolution). **No new `setup-check` CI job** in this slice.
- **Modified docs:** `STACK.md` documents `sync-kernel.sh` and `setup.sh` usage; adds `jq` to the prerequisites list.
- **New files written into generated apps (by `new-app.sh` and `sync-kernel.sh`):** `.kernel-version`, `.kernel-sync-hashes.json` (committed to the consuming app's git).
- **Out of scope here:** wiring the `smoke-app` job to the full slice-5 pipeline (slice 5), supporting partial sync (single file / single tier — possible follow-up), automatic conflict resolution beyond `--accept-kernel`, the synth-d retrofit (slice 6).
